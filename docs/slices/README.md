규칙:
- S1~S3는 `IF-DB-001` schema를 바꾸지 않는다(S0에서 전체 schema를 먼저 둔다 — "아직 없는 표면은 지금이 싸다").
- S4는 S2·S3 뒤. S5는 S1~S4의 API가 있어야 끝까지 검증된다. S6은 S2 뒤 언제든.
- S7의 Pi 실배포(systemd 설치)는 사용자 확인 뒤 실행한다. 그 전 슬라이스는 Pi에 `/tmp` 아래 일시 실행만 허용한다. (2026-10-16 사용자 확인 뒤 첫 설치로 충족.)
- S8은 S1·S5·S7 뒤. `IF-DB-001`을 바꾸지 않는다. Pi 배포는 S7처럼 사용자 확인 뒤 별도로 한다.
- S9는 S1·S5·S6·S7 뒤. `IF-DB-001`을 v2로 올리는 첫 슬라이스다(v1 행 보존, 데이터 migration 없음). Pi 배포는 사용자 확인 뒤 별도로 하고, 배포 직전 `platformd backup`을 받는다(v2 DB는 이전 바이너리가 거부한다).
- S10은 S2·S4·S5·S9 뒤. `IF-DB-001`을 바꾸지 않는다(schema v2 그대로). Pi 반영은 새 바이너리 배포 뒤 설정 `[owner]` 추가와 재시작이며 오케스트레이터가 한다(S9 이하 바이너리는 모르는 `[owner]` 표로 기동을 거부하므로 설정을 먼저 넣지 않는다).
- S11은 S6·S9·S10 뒤. `IF-DB-001`을 v3로 올린다(`agent_avatars` 신설, 기존 행 보존). Pi 배포는 사용자 확인 뒤 별도로 하고, 배포 직전 `platformd backup`을 받는다(v3 DB는 이전 바이너리가 거부한다). 설정 변경은 없다.
- S12는 S1·S2·S4·S10·S11 뒤. `IF-DB-001`을 v4로 올린다(`messages`를 다시 만들어 `sender_id` foreign key만 제거, 모든 행 보존). Pi 배포는 사용자 확인 뒤 별도로 하고, 배포 직전 `platformd backup`이 **필수**다(v4 DB는 이전 바이너리가 거부하고 되돌림은 그 snapshot 복원뿐이다). 설정 변경은 없다.
- S13은 S1~S4·S10·S11·S12 뒤. `IF-DB-001`을 v5로 올린다(`rooms` 신설과 backfill, 기존 행 보존, table 재구성 없음). wire를 호환 shim 없이 한 번에 자르므로 배포 동안 agent를 허브에서 끊는다(사용자 결정 2026-10-20). Pi 배포는 사용자 확인 뒤 별도로 하고, 배포 직전 `platformd backup`이 **필수**다(v5 DB는 이전 바이너리가 거부한다). 배포 뒤 CLI 재빌드 → hub-mcp → hub-discord 순으로 맞추고 "에이전트 공지"를 보낸다. 설정 변경은 없다.
- S14는 S13 뒤(같은 `api::agents`·`store::queries::agents`·`store::migrations`·`platform-wire::agents`를 건드린다). `IF-DB-001`을 v6로 올린다(`agents.last_seen_at` 컬럼 하나, 기존 행 NULL). Pi 배포는 사용자 확인 뒤 별도로 하고 배포 직전 `platformd backup`이 **필수**다(v6 DB는 이전 바이너리가 거부한다). 설정 변경은 필요 없고, `[presence]`를 넣는다면 새 바이너리 배포 뒤에 넣는다.
- S15는 S13·S14 뒤(`commit_send`·`api::history`·`platform-wire::messages`를 다시 건드린다). `IF-DB-001`을 v7로 올린다(컬럼 둘·표 하나·index, 옛 답글의 `thread_id`와 참여자 backfill, table 재구성 없음). Pi 배포는 사용자 확인 뒤 별도로 하고 배포 직전 `platformd backup`이 **필수**다(v7 DB는 이전 바이너리가 거부한다). 설정 변경은 없다.
- S16은 S15 뒤(`platform-wire::{messages, inbox}`·`store::queries::{messages, inbox}`·콘솔 메시지 렌더링을 다시 건드린다). `IF-DB-001`을 v8로 올린다(표 셋·seed 7행·`sequences` 행·`inbox_rows` 컬럼 하나, 기존 행 보존). inbox에 메시지가 아닌 사건이 처음 들어가므로 S13 이전 소비자가 남아 있지 않은지 배포 전에 확인한다. Pi 배포는 사용자 확인 뒤 별도로 하고 배포 직전 `platformd backup`이 **필수**다(v8 DB는 이전 바이너리가 거부한다). 설정 변경은 없다.
